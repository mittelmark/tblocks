Introduction

tblocks is a Tcl application and Tcl package which can be used to translate simple Markdown files into SVG graphics.

Here the typical Hello World example with Markdown code which be automatically converted to a SVG graphics using a command line like tblocks hello.md hello.svg:

## Hello

- entry 1
- entry 2
- entry 3

There can be as well some more text
in the lines below of the list.

## World!

- entry 4
- entry 5
- entry 6

There can be as well some more text
in the lines below of the list.

You can see the default color coding and the default diagram style which is blocks. By using a YAML header you can changing these defaults.

Styling the Diagram

There are two ways to change the diagram type, the font and the colors for the output. Either you provide the application the appropriate command line option, or you give these settings within a YAML header section at the beginning of the Markdown file.

Styling Colors

Here is a modified version where we set the colors for the first diagram to magentish:

---
color1: "#DDDDFF" "#BBBBEE" "#404090"
---

There can be as well some more text
in the lines below of the list.

## World!

The default colors are based on the standard order of ANSI colors, so we have black, which is used for the text, then pastel version of red, green, yellow, blue, magenta and cyan. Here you see an extension of the first plot. For space issues I hide most of the Markdown code here:

Diagram Types

The mode entry in the YAML header selects a diagram layout. The following examples show layouts which are useful beyond the default block diagram.

Sequence

The sequence layout presents a row of steps and can place a small icon in a heading:

---
mode: sequence
---

## Prepare

- Collect the input
- Validate the data

## Process icon:yes

- Apply the calculation
- Store the result

## Finish

- Review the output
- Report success

Table

The table layout places two or more titled columns next to each other. Each item should be a Markdown list entry:

---
mode: table
---

## DO icon:yes

- Use references for read-only parameters.
- Keep class variables private.
- Prefer standard-library containers.

## DON'T icon:no

- Pass large objects by value.
- Use C strings when std::string is available.
- Leave data members public in a class.

Input and Output

The inout layout is intended for an input, a processing function, and an output:

---
mode: inout
---

## KNOWN

Input

The data available
at the start.

## UNKNOWN

Function

The transformation
to be developed.

## KNOWN

Output

The expected result
after processing.

Timeline

The timeline layout distributes dated or ordered events along a horizontal timeline:

---
mode: timeline
---

## 1. Planning

2024 - Requirements
2025 - First prototype

## 2. Development

2025 - Implementation
2026 - Integration

## 3. Release

2026 - Documentation
2026 - Public release

Comparison

The compare layout uses ### subheadings for labeled parts of each item:

---
mode: compare
---

## Inheritance (Is-A)

### Definition

Class B is a subtype of class A.

### Implementation

Reuse and specialize inherited behavior.

## Composition (Has-A)

### Definition

Class B contains or delegates to class A.

### Implementation

Combine independent components.

Circular

The circular layout uses one top-level # heading for the central circle and one or more ## headings for surrounding subsections. Three, four, and five subsections use compact fixed layouts; additional subsections are placed around the circle:

---
mode: circular
---

# 1. Core Topic :: With Two Lines

## 1.1 First Area
The first subsection is centered below
its heading.

## 1.2 Second Area
The next subsection is placed clockwise.

## 1.3 Third Area
The remaining subsections follow around
the central circle.

A second circular diagram can use a pastel palette by overriding color1 with text, fill, and border colors:

---
mode: circular
color1: "#17452d" "#ddf5df" "#86c99a"
---

# 1. Sustainable :: Development

## 1.1 Social
Support fair access and inclusive participation.

## 1.2 Economic
Build durable value and resilient processes.

## 1.3 Environmental
Reduce waste and preserve natural resources.
